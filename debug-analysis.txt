## Comprehensive Analysis: 404 on POST /api/admin/messages/conversations/:id/messages

### Root Cause Identified

The 404 Not Found error is happening **inside the route handler** because the conversation with ID `cmwezh3hb0000f7013jdo0u1t` does not exist in the database.

### Code Flow

1. **Route matches** ✅ - Express correctly routes `POST /api/admin/messages/conversations/:id/messages` to the admin handler

2. **Database query fails** ❌ - At `server/src/routes/admin.ts:233`:
   ```typescript
   const conversation = await prisma.conversation.findUnique({ where: { id: conversationId } });
   if (!conversation) return next(notFound('Conversation not found'));  // ← 404 here
   ```

3. **Result** - Since the conversation ID doesn't exist in the Prisma database, `findUnique` returns `null`, triggering the 404 response.

### ID Format Verification
- The ID `cmwezh3hb0000f7013jdo0u1t` is **25 characters** 
- Prisma uses `@default(cuid())` for Conversation IDs (confirmed in `prisma/schema.prisma:796`)
- CUIDs are typically 27 characters - this is a valid CUID format (may be truncated or a variant)

### Likely Scenarios

| Scenario | Probability | Description |
|----------|-------------|-------------|
| Conversation never created | High | The conversation ID is invalid or was never persisted |
| Conversation deleted | Medium | Conversation was deleted after being created |
| Wrong conversation context | Medium | Conversation belongs to a different organization/user |
| Stale UI state | Medium | Frontend has outdated conversation selection |
